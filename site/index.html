ML Learning Paradigms

Supervised Learning

Trained on labeled data — input mapped to known output.

Algorithms: Linear/logistic regression, decision trees, SVM, neural nets

Use: Spam detection, price prediction, classification

Unsupervised Learning

Trained on unlabeled data — finds hidden patterns.

Algorithms: K-means, hierarchical clustering, PCA, autoencoders

Use: Customer segmentation, anomaly detection

Reinforcement Learning

Agent learns by trial and error — rewards and penalties.

Algorithms: Q-learning, SARSA, PPO

Use: Game AI, robotics, autonomous vehicles

2 Task 1.2 — Practical Use Cases for AI

When AI/ML Provides Value

  • Assist human decision making — medical diagnosis support, financial risk assessment
  • Solution scalability — processing millions of documents, images, or transactions
  • Automation — repetitive tasks like data entry, routing, content moderation
  • Pattern recognition — fraud detection, predictive maintenance, demand forecasting

When AI/ML Is NOT Appropriate

  • When a deterministic outcome is needed (use rules/business logic)
  • When cost outweighs benefit — simple problems don't need ML
  • When insufficient data exists to train a reliable model
  • When explainability is critical and black-box models are unacceptable

Token-Based Pricing

Key Concept
GenAI services charge per token (input + output). Input tokens are usually cheaper than output tokens. Prompt caching reuses results for repeated prefixes. Batch pricing offers ~50% discount for non-urgent work.

Retrieval Augmented Generation (RAG)

RAG — The Most Important Pattern
Retrieves relevant documents from a knowledge base and injects them as context so the FM answers based on your data.
  1. Ingest — Load documents (PDF, text, HTML)
  2. Chunk — Split into smaller pieces
  3. Embed — Convert chunks to vector embeddings
  4. Store — Save in a vector database
  5. Query — User asks a question
  6. Retrieve — Find similar chunks via vector search
  7. Augment — Combine query + retrieved context
  8. Generate — FM produces grounded answer

Vector Databases on AWS

OpenSearch Service Aurora (pgvector) Neptune RDS for PostgreSQL

2 Task 3.2 — Prompt Engineering

Techniques

TechniqueDescriptionExample
Zero-shotNo examples, just the task"Classify this review: ..."
One-shotOne example provided"Example: 'Great!' → Positive. Now: 'Terrible' →"
Few-shotMultiple examples (3-5)Several input/output pairs before the query
Chain-of-thoughtAsk model to show reasoning steps"Think step by step. First... Then..."
TemplatesReusable prompts with variables"You are a {role}. Analyze {topic}."

Best Practices

  • Be specific — Clear instructions → better outputs
  • Use examples — Few-shot dramatically improves quality
  • Set the role — "You are an expert financial analyst"
  • Specify format — JSON, bullets, table, paragraph
  • Use guardrails — Content filters, topic restrictions
  • Use negative prompts — Tell the model what to avoid

Prompt Security Threats

Security Risks

Legal Risks of GenAI

  • IP infringement — Generated content may resemble copyrighted material
  • Biased outputs — Discriminatory outputs → legal liability
  • Loss of trust — Inappropriate outputs damage reputation
  • Hallucinations — False information as fact → legal consequences

Bias vs Variance

High Bias (Underfitting)

Model too simple — consistent errors. Causes: oversimplified model, insufficient features, biased data.

High Variance (Overfitting)

Model too complex — memorizes noise. Causes: too many parameters, insufficient data.
